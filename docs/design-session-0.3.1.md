# 0.3.1 版本设计规范

本文档记录 0.3.1 版本的核心架构设计、算法模型与交互规格，已经过持续追问（Grilling）达成共识。

---

## 1. 群系斑块拓扑图分析架构（Biome Patch Graph）

### 1.1 核心设计理念
自动区域不再以离散区块（Chunk）为最小洪水填充单元，而是以空间上连续同群系区块聚合成的**群系斑块（Biome Patch）**为拓扑图节点，进行宏观地理区域识别。

### 1.2 图构建与合并算法流程
1. **斑块聚类（Patch Clustering）**：
   - 遍历采样区域内的所有已探索区块（`ChunkCell`）；
   - 基于生物群系标识符（`BiomeId`）使用 4-连通（Edge Sharing）将相邻同群系区块聚合成 `BiomePatch`；
   - 每个斑块包含：`biomeId`、主导 `TerrainKind`、区块集合 `Set<ChunkCell>` 以及包围盒。
2. **微小斑块吞没（Tiny Patch Absorption）**：
   - 面积 $\le 3$ 个区块且其外围所有相邻区块均属于同一个外部斑块的异质微小斑块，直接被该主导斑块吸收合并，消除内部未着色空洞。
3. **河流粘合桥梁（River Bridge）**：
   - 宽度 $\le 128$ 格（$\le 8$ 个区块）的狭窄河流斑块，若其两侧邻接的主导斑块分类相同（例如两侧皆为森林或皆为平原），河流斑块作为拓扑桥梁连接两岸，并将河道区块合并纳入该区域。
4. **拓扑图归并（Component Merging）**：
   - 具有相同分类（或相容规则）且 4-连通接壤的群系斑块合并为候选区域（`Candidate`）；
   - 水体分类遵循既定大洋基底规则：所有海洋与水体先聚合成宏观大洋，仅当冻洋群系斑块面积占比 $\ge 1/3$ 时才将冻洋独立剥离。
5. **跨度与有效性审查**：
   - 以候选区域所有区块的外接矩形范围 $\max(dx, dz)$ 衡量实际探索跨度；
   - 仅当跨度达到该地形的配置门槛时，才正式采纳为自动区域并命名。

## 2. 全量已注册群系浏览器与增量覆盖

### 2.1 界面升级与定位
- 设置界面第 5 个 Tab 升级替换为**“群系分类”**全量浏览器，维持 5 Tab 经典宽度。
- 动态获取当前客户端已注册的全部生物群系（涵盖原版与所有已加载的地形模组）。
- 若在游戏主界面未载入世界时打开，展示客户端内置群系并在顶部提示“进入存档后可查看并调整当前整合包的所有模组群系”。

### 2.2 交互与功能规格
- **实时搜索栏**：支持按群系 ID（如 `forest`、`plains`、`terralith:`、`biomesoplenty:`）快速模糊检索。
- **分类过滤按钮**：支持一键切换“全部”、“已修改”、“山地”、“大洋”、“平原”、“森林”、“未分类”等过滤视图。
- **即时切换分类**：点击每行右侧的类别按钮，循环切换（山地 -> 大洋 -> 冻洋 -> 原野 -> 森林 -> 花草甸 -> 沙漠 -> 湖泊 -> 北地 -> 暂不分类）。
- **增量持久化（Biome Overrides）**：
  - 仅将玩家显式修改的群系保存到 `automatic.json` 的 `biomeOverrides: { "biome_id": "KIND" }` 中；
  - 未修改项保持内置启发式推断，保证模组更新时的向前兼容性；
  - 提供单项“重置”按钮与顶部“全部恢复默认”按钮。

## 3. 白名单素材与命名规范

### 3.1 词根单字库（`roots.json`）
- 彻底清理旧误加的双字组合词条；
- 提炼并收录 65 个充满自然地理意象的纯净单字词根（寒、霜、雪、风、龙、星、月、岩、泉、林、松、鹿等），赋予精准的地形与气候偏好。

### 3.2 默认名库（`names.json`）
- 剔除粗糙与重名词条，规范收录 119 个精选双字专名（总数达 246 条）；
- 天象、神幻、走兽、水体类默认名不限地形；草木类限定陆地；山石类限定山地与森林；气候偏好根据字面语义严格打标。
