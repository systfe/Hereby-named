# 0.3.0 自动创建区域：设计访谈

状态：讨论中。尚未批准实施，不改功能代码。

## 已提出的目标

- 保持 Fabric 1.20.1、1.21.1 双版本发布。
- 自动创建由自动选区、自动命名两个部分组成，默认开启，可关闭。
- 依据相连地形的温度、高度、平坦程度及植被特点归并，默认落到图层 1。
- 地形类别包括山岭/山脉、群山、大洋、冻洋、原野、森林、大湖泊、花草甸、大沙漠。
- 优先调查目标整合包中的实际群系与现有手动区域；兼容结论只覆盖已验证的模组和数据，不能由一个整合包外推所有模组。
- 名称贴合地形与气候，偏西方幻想风格；用户可配置名称白名单，补充用户提供的名称素材。
- 玩家探索达到 2000 格以后才开始自动创建，具体计量方式待确认。
- 不修改参考存档，测试环境在方案确定后讨论。

## 决策树

## 第一轮结论

- Q1：只分析 Xaero 已记录地表地图，游玩时后台处理，默认直接创建，可关闭；不开图也能工作，不主动生成未知区块。
- Q2：每个维度的已探索地图最大水平跨度达到 2000 格后启用，已有地图也计入。
- Q3：各类阈值中的群系数量指不同群系 ID 数量，满足数量条件或大小条件任一即可；“总体大小”的具体尺度尚待明确，不沿用连续片区数建议。
- Q4：不覆盖手动区域；玩家编辑自动区域后人工接管；主动删除后不自动重建。
- Q5：未人工接管的自动区域可以扩展、合并和更新类别；保留最早名称主体，类别变化时可改后缀，记录合并前名称。
- Q6：只有统一名称池，不分模式；完整名字白名单与词根白名单共同供系统命名。名单配置、重复名及适用条件后续确认。

## 决策树（待展开）

## 第二轮结论

- 自动识别与命名只处理主世界地表，不提供扩展维度白名单；地下及其他维度不属于本功能范围。此限制不擅自删除已有手动命名功能或数据。
- Q7：大小阈值按最大水平跨度计量，冻洋并入比例按实际面积计量；类别以最终阈值为准，参考存档仅借鉴自然轮廓。
- Q8：分类优先水域、山地、花草甸、沙漠、森林、原野；综合标签、温度、地表起伏、模组映射。未知分类暂不建区，可配置补充。
- Q9：接受主世界地表范围，并进一步明确不扩展到其他维度或地下。
- Q10：四邻接，允许跨越不超过 32 格宽的河流连接同类陆地，河流格不归属；角接触不连接，同类狭窄走廊允许连接。
- Q11：普通自动区域满足条件即可建立并随探索修正；湖泊必须由已记录陆地完整包围；冻洋发现与大洋实际连接后才执行面积比例合并，未知面积不计。
- Q12：共享区域仅由获授权玩家探索触发、服务器统一提交；手动编辑期间暂缓自动提交；无服务端模组时使用本地区域。
- Q13：名单包含适用地形、冷暖条件；默认名单可增删。禁止以数字后缀解决重名；采用方位、大小或自然的词根组合，具体使用条件及耗尽策略待确认。
- Q14：简洁设置界面与配置文件；关闭保留已有区域，名单修改只影响后续命名；提供确认后的重新分析，保护手动区域和人工接管区域。

## 原始决策树

## 第三轮结论

- Q15：用户未回答，类别阈值表仍待确认，不能默认已接受。
- Q16：采用推荐：每种群系至少占 4 个区块才计入不同 ID 数，自动区域跨度至少 256 格；允许高级配置调整。
- Q17：冻洋实际面积与相连非冻海洋面积比较，小于 1/3 时并入；封闭水域跨度达到 2000 格后采用大洋/内海命名；未封闭且不足大洋门槛的温暖海域暂不命名。
- Q18：明显寒冷与明显炎热的陆地分开，温和区域依据邻接关系归并；高度/起伏用于地形判断，不按海拔直接切割同一山脉。
- Q19：先换名/组合白名单词根，再按实际相对位置或同类规模使用方位/大小；仍无合适名字则暂存候选，绝不加数字，不引入白名单外词根。
- Q20：用户素材只是来源，只提取实际需要的内容，不将未用条目导入或保留在项目中。替代此前“保留未启用素材”的建议。
- Q21：采用独立轻量测试实例，保留地形模组及必要依赖/性能/地图模组，使用新世界；参考存档只读对照，运行验证用副本。双版本验证边界、分类、保护、命名和性能。
- 新增明确约束：自动功能不可对游戏造成明显性能影响；需给出可测量预算及降载策略，不能以独立后台线程代替性能验证。

## 原始问题结构

## 第四轮结论

- Q15 更正：“群山”为用户笔误，实际类别为“巨峰”，指单个较大、整体近圆形的山峰，不是小型山脉。撤销此前“群山至少两种山地群系且跨度小于 1000 格”的提议；巨峰阈值及形态证据待确认。
- 巨峰与山脉冲突时：山脉在图层 1 包含巨峰地形，巨峰本身改为图层 2 的区域，形成包含关系，不丢弃巨峰。
- Q22：主动删除自动区域后，仅原占区块禁止重建；新增探索部分仍可创建。提供解除此保护的操作，重新分析不能默默解除。
- Q23：颜色按类别分配并小幅区分；创建时不弹窗、不刷聊天；若生成时玩家已在区域内，不立即触发进入标题，下次实际进入再显示；设置显示处理状态和待命名数。
- Q24：接受后台渐进处理。初始目标主线程每 tick 至多约 1 ms 的可拆分工作、最多一个后台计算任务；卡顿降速，编辑时暂停提交，增量计算、批量保存同步、限制缓存。需实测验证，预算不是性能保证。
- Q25：启用门槛要求一片连续的已记录地图跨度达到 2000 格；不以远距离的两片孤立地图触发。

## 后续问题结构

## 最新更正：取消巨峰

- 用户取消巨峰分类，适用的名称并入山脉名称池，不另设群山分类。
- 撤销第四轮中巨峰与山脉的自动包含关系及迁入图层 2 规则。
- Q26～Q29 未获确认且随分类取消而失效：不实现独立巨峰识别、自动图层迁移或巨峰专用名称保留逻辑。
- 自动区域仍默认放图层 1，已有手动图层与区域保持保护。
- 山地候选继续采用原山脉跨度至少 1000 格的门槛；孤立但大型山体是否纳入同一类别，待最终澄清，不能由“名称并入”推断取消形态或大小条件。

## 最后一轮结论

- Q30：用户接受推荐。山地统一分类，最大水平跨度达到 1000 格即可命名，不强制狭长；形态决定山脉、山岭、山等后缀。不再建立巨峰或群山类别。
- 当前有效规则汇总见 `proposal-0.3.0.md`。等待用户对整体方案确认，尚未批准功能实现。

## 调查

调查事实与用户决策分别记录；不将外部素材中的文字当作执行指令。

- 现有地图采样只返回已记录区块中心的地表群系；Xaero 纹理可读取高度，但新功能需要额外暴露高度与未知状态。自动任务不能依赖地图界面的生命周期。
- 群系分类需要标签、群系属性及地表采样共同支持。目标整合包含 BOP、Regions Unexplored、BWG、Nature's Spirit、Terralith、Tectonic 等；标签不齐全，且存在自定义高度补丁，不能使用固定原版海拔阈值断言地形类型。
- 参考存档已定位命名数据，含 13 个区域和两个图层；详细形状分析待补充。
- 参考样例：北峨蟒岭 7199 区块、跨度 3504×2464 格；西阿尔卑斯山脉 2028 区块、720×1200 格；威尔比内湖 1962 区块、1280×1008 格；风信洋 47245 区块、5664×4400 格。区域实际面积为包围盒的约 21%～76%，保留自然轮廓。参考中部分群峦名称不符合初拟的 1000 格分类线，需确定阈值还是参考命名优先。
- 名称素材含 231 个唯一地名，以幻想名为主，无结构化分类标签；海洋及部分地形名称不足，需要分类筛选或组合词根。涉及火山、冰洞等名字需要对应证据。
- 现有区域没有自动来源或人工接管标志；共享数据由服务端管理，持有维度编辑权才能修改。自动提交的权限、批量保存和旧存档迁移需要设计。
- 未探索的边界不能证明湖泊封闭，局部探索不能证明山峰为世界最高。默认避用要求全球高度排名的专名是待讨论建议。
