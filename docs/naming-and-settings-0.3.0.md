# 山地扩张改名与游戏内设置

## 山地命名

只在自动管理的山地区域后续扩张时判断，玩家手动接管的区域不参与。初始名以“山／峰”结尾时，新增的已记录地表若显示为绵延或宽广山地，可以改名一次，例如“赤霞峰 → 赤霞岭”。优先保留原词根；若替换后与现有区域重名，使用符合类型和冷暖的白名单词根另起名字，没有可用名字则保留原名并继续扩张。

默认形态规则如下，全部可以在“全局参数”中调整。这是对已知轮廓的判断，不宣称已找到整座山脉的最终边界。

- 包围盒长边大于短边 1.8 倍：跨度达到 2000 格用“山脉”，否则用“岭”。
- 其他轮廓：跨度达到 2000 格或面积达到 4096 个区块，用“峦”。
- 不满足上述条件则保持单山名称。

自动改名次数保存在权威区域数据中。重新加载、冷暖分类变化、继续扩张均不能重置次数；合并时任一来源已经改名，则合并后的区域也不再自动改名。旧名字保留为历史名称。人工修改仍可自由命名，并使区域转为手动管理。

存档升级为 HBN3，能读取 HBN1 和 HBN2；旧 HBN2 自动山地起始为尚未进行本次形态改名。共享通道升级为 `regions_v4`，客户端和服务端需一起更新。回退旧模组前需恢复旧格式区域备份。

## 名称风格

默认名白名单保存游戏、神话和地球地名原文，选中后追加类别词尾。峨邙、岷峨、岱北、穆朗仅适用于山地，嵩湘、梓浦仅适用于湖泊；其余默认名没有地形或气候偏好。词根有独立的地形与气候偏好，随机组合 1–3 个不重复词根后追加类别词尾。森林使用“森林、林”；平原使用“平原、之原”；北地使用“冻土、北地、地、原、冰原”。已有裸默认名会在重新分析后补齐类别词尾。

名称先挑选未使用的默认名，再尝试未使用的词根组合；两类唯一名称都耗尽后才允许重名。分类变化不会使既有自动区域重新取名，山地扩张的一次性形态改名规则除外。所有自动名称均禁止数字后缀。

只自动更新与上一版默认名单完全相同的文件；玩家修改过的名单继续保留。可在游戏内点击“恢复默认”替换草稿，确认保存后才会改动配置。已有普通区域不会为了新风格而批量改名。

## 游戏内界面

打开 Xaero 世界地图 → 左侧自动创建区域设置 → “区域判断设置”。默认名与词根按钮也会进入同一个编辑界面。

界面包含“区域门槛、全局参数、默认名、词根、群系规则”五页签，较多条目会分页。数字输入框悬停显示含义和范围。数量与最低跨度满足其一即可；跨度上限不包含边界，0 表示停用相应条件。

默认名／词根条目可以修改文字、适用地形和气候，多种偏好可同时选中，留空表示不限。北地包括寒冷平原、冻土、森林、河流和湖泊，寒冷山地与冻洋保留各自类别；显式群系规则优先。群系规则可输入完整群系 ID 或末尾 `*`，选择分类后应用到草稿。新增、编辑、删除和恢复默认首先只修改草稿；返回设置后点击“保存并应用”写入文件并重新分析，点击“取消”或 Esc 放弃本次草稿。

保存前统一校验三个配置文件，先暂存再替换，文件写入出错会尝试恢复原值并显示错误。日常配置不再打开系统文本编辑器；JSON 文件仍保留供高级用户与整合包维护者使用。
